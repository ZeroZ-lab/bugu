# 架构

一个 Go 程序,多种运行形态,共用一个后台。设计意图和需求见 [PRD](PRD.md) 第 5 章,各项决定的理由见 [adr/](adr/)。本页只描述代码现状。

## 运行时

程序入口为 `main → cli`。`bugu serve` 在当前进程里启动后台(`daemon`);`bugu app`(或不带参数)启动桌面应用(`gui`),它同样在进程里承载后台,除非本机已有后台在运行,那时它只做界面。其余命令是客户端:通过 `client` 调用后台的 HTTP 接口,自己不读写任务文件。

```
bugu add / list / run / …          bugu serve
        │                               │
     client ──── HTTP JSON + 令牌 ──→ server ──→ daemon 的引擎
                                                   ├─ schedule  现在该触发什么
                                                   ├─ exec      预检、启动进程、超时、采集输出
                                                   │   └─ runner  运行器配置 → 要执行的命令
                                                   └─ store     任务文件、运行存档、调度进度
```

后台每 15 秒醒来一次,用当前墙上时间和每个任务"已评估到的时间点"计算该不该触发,不设长定时器([ADR 0003](adr/0003-injected-clock.md))。评估点在触发前落盘,所以重启不会重复触发;停机或睡眠跨过多个时间点时只补跑最近一次。同一任务上一次未结束时,新的定时触发记为跳过。

本机客户端靠数据目录(默认 `~/.bugu`,可用 `BUGU_HOME` 指定)里的两个文件找到后台:`endpoint.json` 是后台实际监听的地址,`token` 是令牌。数据目录由一个文件锁独占,同一份数据只会有一个后台。目录布局见 `internal/store/store.go` 的注释,接口列表见 `internal/server/server.go`。

每个接口请求先校验来源再校验令牌,之后才到达处理器:带 `Origin` 的请求必须与请求目标同源,令牌只从 `Authorization: Bearer` 请求头读取([ADR 0001](adr/0001-http-and-token.md),PRD 7.10)。

## 界面

前端源码在 `web/`,用 React 和 TypeScript 编写,Vite 构建。构建产物 `index.html`、`app.js`、`style.css` 写进 `internal/server/static/` 并提交进仓库,编译时嵌入程序,由后台在同一端口提供,所以构建程序不需要 Node([ADR 0010](adr/0010-web-react-vite.md))。`web/src/api.ts` 是接口客户端,`taskForm.ts` 是表单与任务定义之间的转换,`ui/` 是共用组件,其余是页面组件。`web/e2e/` 是浏览器测试:用构建好的程序起一个临时数据目录、随机端口的后台,在 Chromium 里走主要流程。前端只通过 JSON 接口工作,所以浏览器和应用窗口里是同一份。这三个静态文件不需要令牌;令牌由桌面外壳放在网址片段里交给页面,或由用户在页面上粘贴([ADR 0007](adr/0007-static-pages-without-token.md))。

桌面外壳 `gui` 是全项目唯一引用桌面框架 MyGo 的包,只做开窗口、菜单栏图标、系统通知、开机自启和退出前确认。用 `headless` 构建标签编译时不包含它和框架(`make build-headless`)。`make app` 把程序打成应用包,配置在 `mygo.json`。

运行结束后,`notify` 按任务的通知设置决定要不要通知、内容是什么;后台通过 `daemon.Options.Notify` 把结果交给承载它的外壳去显示。`bugu serve` 没有外壳,不发系统通知。

尚未实现的部分见 [PRD](PRD.md) 第 11 章。

## 包

全部在 `internal/` 下,按职责平铺。

| 包 | 职责 | 可以引用 |
|---|---|---|
| `clock` | 时钟接口、真实时钟、测试用假时钟 | 无 |
| `task` | 数据模型:任务、触发、步骤、运行 | 无 |
| `schedule` | 给定任务和当前时间,决定现在该触发什么。纯函数,不执行、不落盘 | `clock` `task` |
| `runner` | 读取运行器配置,把 AI 命令行步骤渲染成要执行的命令,展开模板变量。不启动进程 | `task`,以及仓库根目录的 `runners`(预设) |
| `exec` | 预检、经登录 shell 启动进程、超时、终止进程树、采集输出、检查运行器能否使用 | `clock` `task` `runner` |
| `store` | 任务文件、运行存档、调度进度、令牌文件的持久化,数据目录的独占锁 | `clock` `task` |
| `notify` | 决定一次运行要不要通知、通知写什么。纯函数,不负责显示 | `clock` `task` |
| `api` | HTTP 接口的请求与响应类型,以及客户端和后台共同约定的文件名。只有类型和常量,没有逻辑 | `task` |
| `server` | HTTP 处理器、来源校验、令牌认证。通过自己定义的 `Backend` 接口调用后台 | `api` 与上面全部 |
| `daemon` | 引擎(触发、运行管理,实现 `server.Backend`),并把以上各部分组装成一个运行中的后台 | `server` 与上面全部 |
| `client` | 接口的 Go 封装 | `api` `task` |
| `gui` | 桌面外壳:窗口、菜单栏、系统通知、开机自启。唯一引用桌面框架的包 | `client` `api` `task` `daemon` `notify` |
| `cli` | 子命令。通过 `client` 工作;仅在启动后台时引用 `daemon`,仅在打开桌面应用时引用 `gui` | `client` `api` `task` `daemon` `gui` |
| `fakeagent` | 测试用的假 agent,一个独立的小程序 | 无 |
| `archtest` | 架构检查,只有测试 | 无 |

"可以引用"一栏以 `internal/archtest/archtest_test.go` 里的允许表为准,两处须保持一致。

仓库根目录的 `runners/` 不在 `internal/` 下:它存放自带的运行器预设,加一个把它们嵌入程序的 Go 文件。厂商和产品的名字只出现在这里的配置文件里。

## 运行器

运行器是一个 JSON 文件,描述怎样调用一个命令行工具:启动命令、提示词怎么传(参数、标准输入或文件)、各权限级别对应的参数、退出码之外的成功条件、检查能否启动的命令。字段的含义见 `internal/runner/runner.go`。自带的预设在 `runners/`,用户自己的放在数据目录的 `runners/` 下,同名时用户的优先。配置在每次使用时重新读取,修改后不需要重启后台。

AI 命令行步骤默认以只读级别运行,放开要在任务里显式写出,且不能超过运行器配置里的上限([ADR 0008](adr/0008-agent-permission-levels.md))。限制由那个命令行工具自己执行,Bugu 只传递参数。

## 扩展边界

当前代码没有插件运行时或插件加载接口。运行器配置与应用插件的区别、对 Magpie 设计的取舍,见 [ADR 0006](adr/0006-extension-boundaries.md)。

## 执行核心

`exec.Executor` 接收注入的时钟和任务,校验后执行单个步骤(脚本或 AI 命令行),返回运行结果。执行器不解释触发和通知;它只往运行的存档目录里写一个文件,即 AI 命令行步骤实际发出的提示词。

启动之前先预检:工作目录是否存在,AI 命令行步骤的运行器命令能否找到。不通过就不启动,本次记为失败并说明原因。

后台由 `bugu serve` 或桌面应用启动时,子进程经用户的登录 shell 启动(`$SHELL -l -c 'exec "$@"'`),所以 PATH 和登录态与终端里一致;任务自己的环境变量在 shell 启动之后再设置,不会被启动文件覆盖。只支持 sh、bash、zsh、dash、ksh;其他 shell 下直接启动,子进程继承后台的环境。超时使用可停止的时钟定时器,测试通过假时钟和进程握手驱动。每路输出在内存里只保留开头和结尾,超出上限的中间部分用一行说明代替。

macOS 和 Linux 上每次执行使用独立进程组。超时、取消及父进程退出后均清理组内后代,再收集输出;主动脱离进程组的程序不在此清理保证内。这类程序若仍持有输出管道,采集在父进程回收后的一段宽限期结束,运行的状态、退出码和结束时间仍取父进程的真实结果。执行器不是进程隔离沙箱。
