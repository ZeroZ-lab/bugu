# 设计规范

Bugu 的视觉和界面写法。各项决定的理由见 [ADR 0009](adr/0009-brand-two-notes.md)。前端代码的结构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 一条规则

**空心表示还没发生或正在发生,实心表示已经有了结果。** 图形、菜单栏、状态标记、未读标记都从这条规则来。新加的界面元素先套这条规则,套不上再另想。

## 名字

| 场合 | 写法 |
|---|---|
| 中文正文、窗口标题、通知 | 布谷 |
| 英文正文 | Bugu |
| 字标、命令行、包名 | `bugu`,小写,等宽字体 |

不写成 BUGU、BuGu、布谷 AI。

## 图形

几何定义以 [resources/logo.svg](../resources/logo.svg) 为准:48×48 的画布,左上实心圆(圆心 17,19,半径 9),右下空心圆(圆心 33,31,半径 5.5,描边 3.5)。

- **颜色**:单色,用墨色或反白。不加渐变、阴影、描边,不给两个圆配不同的颜色(菜单栏的"有失败"状态除外)。
- **最小尺寸**:16px。更小时不画。
- **留白**:四周至少留出大圆的半径。
- **字标组合**:图形在左,`bugu` 在右,图形高度约为字高的 1.3 倍,两者间距为大圆的半径。
- **应用图标**:墨色圆角方块,反白的图形居中,占方块宽度的 60% 左右。深色和浅色模式用同一个图标。

## 菜单栏图标

作为 macOS 模板图标使用(纯黑加透明,由系统着色)。四种状态只改变右下那一声:

| 状态 | 右下那一声 | 旁边 |
|---|---|---|
| 平时 | 空心圈,与 logo 相同 | 无 |
| 运行中 | 虚线圈,缓慢转动 | 无 |
| 有新结果 | 实心,半径与空心圈的外沿相同 | 未读条数 |
| 有失败 | 实心,失败红 | 失败条数 |

"有失败"不能用模板图标,深色和浅色菜单栏各准备一张。几种状态同时成立时,按"有失败 > 有新结果 > 运行中 > 平时"取第一个。

## 颜色

品牌色只用墨色。彩色只用来表示状态,不用于装饰、不用于按钮。

| 变量 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `--ink` | 品牌、主按钮、选中、图形 | `#1a1a18` | `#ededea` |
| `--on-ink` | 墨色上的文字 | `#ffffff` | `#141413` |
| `--bg` | 页面底色(纸色) | `#f5f5f2` | `#141413` |
| `--surface` | 卡片、表格、顶栏 | `#ffffff` | `#1e1e1c` |
| `--hover` | 悬停、选中的标签页 | `#efefea` | `#262624` |
| `--line` | 分隔线、边框 | `#e4e4de` | `#34342f` |
| `--text` | 正文 | `#1a1a18` | `#ededea` |
| `--muted` | 次要文字 | `#6e6e68` | `#a2a29b` |
| `--idle` | 等待、暂停的空心圈 | `#9a9a93` | `#77776f` |
| `--ok` | 成功 | `#2e7d4f` | `#5fbf86` |
| `--bad` | 失败、危险操作 | `#c2362b` | `#ff7b6e` |
| `--warn` | 超时、警告 | `#8f5c00` | `#e3b04f` |

- 正文和次要文字与它的底色对比度不低于 4.5:1。`--idle` 只用于图形,不用于文字。
- 深色模式默认跟随系统(`prefers-color-scheme`)。设置页里可以固定为浅色或深色(G16),选择只记在这台设备上,写在 `<html data-theme>` 上;两套取值见上表。

## 运行状态标记

状态用"10px 的圆点 + 文字",不用彩色底的标签。

| 状态 | 圆点 | 文字颜色 |
|---|---|---|
| 等待(任务已启用)、排队中 | `--idle` 空心圈 | `--text` |
| 已暂停 | `--idle` 空心圈 | `--muted` |
| 运行中 | `--ink` 虚线圈,缓慢转动 | `--text` |
| 成功 | `--ok` 实心 | `--text` |
| 已跳过、已错过、已取消 | `--idle` 实心 | `--muted` |
| 超时 | `--warn` 实心 | `--text` |
| 失败、中断 | `--bad` 实心 | `--bad` |

只有失败的文字用彩色:一屏里出问题的那一行应当最先被看到。系统设置了减少动态效果时,虚线圈不转动。

收件箱里未读的结果前面有一个 8px 的 `--ink` 实心点,读过之后去掉。

## 文字

- 界面文字用系统字体:`system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。不打包字体文件。
- 字标 `bugu`、任务名、cron 表达式、时间、命令、输出用等宽字体:`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`。
- 字号:正文 14px,表头和说明 12px,区块标题 18px。不用 12px 以下的字号。
- 字重只用两档:400 和 600。

## 形状和间距

- 圆角:按钮、输入框、标签页 6px;卡片、表格 10px;对话框 12px。
- 边框和分隔线 1px `--line`。不用阴影,对话框的遮罩除外。
- 间距取 4 的倍数,常用 8、12、16、24。

## 组件

组件自己写,不引入组件库。共用组件都在 `web/src/ui/`,从 `./ui` 引用。它们是返回元素描述的函数,包的是原生元素;带状态的页面部件才写成自定义元素([决策记录 0017](adr/0017-web-components-no-framework.md))。

### 规矩

1. **先用原生元素**:对话框用 `<dialog>`,下拉选择用 `<select>`,折叠用 `<details>`,弹出层用 `popover` 属性,日期时间用 `<input type="datetime-local">`。它们的键盘操作和读屏支持由浏览器负责。
2. **先找现成的**:写界面前先看 `web/src/ui/` 里有没有;有就用,不在页面里另写一个差不多的。
3. **重复三次就收进来**:同一种写法在页面里出现到第三处,收成 `ui/` 里的组件,并在下面的清单里登记。
4. **原生做不好的先停下来问**:带搜索的选择框、键盘可操作的菜单、日期选择器这类,自己写容易在键盘和读屏上出错。动手前先问:自己写并配浏览器测试,还是引入现成的无样式组件(要新写一篇决策记录)。
5. **样式写在 `web/src/style.css`**:只用上面的颜色变量和尺寸,不写行内样式。

### 清单

| 组件 | 用途 |
|---|---|
| `Button` | 按钮。`variant` 取 `primary`(墨色底,一屏最多一个)或 `danger`(红色文字,用于删除),默认是 `--surface` 底加 `--line` 边框。默认 `type="button"`,提交按钮要显式写 `type="submit"` |
| `Field` | 表单里的一项:标题、控件、可选的说明。用 `label` 包住控件 |
| `Choice` | 一组横排的单选项,用原生 radio |
| `Modal` | 模态对话框,用原生 `<dialog>`。`wide` 用于运行详情这类内容多的 |
| `Mark` | 状态标记,见上面的"运行状态标记" |
| `ErrorText` | 错误说明,没有内容时不占位置 |
| `Logo` | 图形,颜色随文字 |

### 没有收成组件的写法

- **表格**:行与行之间只用分隔线,不用斑马纹。任务名用 `mono` 类,时间列用 `time` 类(等宽、`--muted`)。可点击的行给表格加 `clickable` 类。任务名太长时截断,完整的名字放在悬停提示里。窗口窄到放不下各列时,每一行变成一张小卡片,不让表格横向滚动。
- **任务分组**:任务列表按工作目录分组,组名是目录的最后一段(重名时多带上级目录),没填目录的归到最后的"未指定目录"。组头是整行的按钮,写任务数,组里有上次失败的任务时标出失败个数,折起来也看得见。点组头折起或展开,折起哪些组只记在这台设备上。只有一个目录时不分组。
- **定时的选择**:表单里不让人直接写 cron。先选重复方式(每天、工作日、每周、每月、每小时、每隔几分钟),再按方式给出时间、星期、几号;重复方式和时间并排(`pair` 类),窄窗口里上下排。最后一项"自定义(cron 表达式)"给会写的人,切过去时填好与刚才的选择等价的表达式,说明里写出它的意思。认不出的 cron 打开时就是自定义。换算在 `web/src/schedulePick.ts`。
- **输入框**:底色要和它所在的面分得开:纸色的页面上用 `--surface`,卡片、顶栏、对话框里用 `--bg`。
- **出错的说明**:放在触发它的按钮旁边,或页面内容的上方;不放在长表单、长列表的末尾。
- **卡片**:`card` 类,`--surface` 底、1px 边框、10px 圆角。
- **空状态**:`empty` 类。用一句话说这里会出现什么,再给出下一步的按钮。

## 文案

- 直说。不用"成功地""请""您",也不用感叹号。
- 按钮写动作,动词在前:"新建任务""立即运行"。
- 出错时先说发生了什么,再说怎么办。不把原始的错误字符串直接给用户看,完整内容放进运行记录。
- 时间写成用户读得懂的样子:"今天 18:31""明天 09:00",cron 表达式只在编辑和详情里出现。
- 英文译文守同样的规矩:句首大写,其余小写(sentence case);不用 please 和感叹号;按钮动词在前("New task""Run now");产品名写 Bugu。
- 中文原文改了,英文译文跟着改,做法见 [决策记录 0014](adr/0014-interface-languages.md)。
