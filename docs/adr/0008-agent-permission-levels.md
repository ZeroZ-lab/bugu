# 0008 AI 命令行步骤默认只读,权限按级别声明

日期:2026-11-12

## 决定

AI 命令行步骤带一个权限级别,由低到高为:

| 级别 | 含义 |
|---|---|
| `read_only` | 不修改文件。默认值 |
| `write_cwd` | 可以修改工作目录内的文件 |
| `full` | 不加限制 |

- 任务没有写明级别时按 `read_only` 运行。需要更高级别必须在任务里显式写出。
- 每个级别对应什么命令行参数,由运行器配置声明。运行器没有声明的级别不能选;Bugu 不替运行器模拟它没有的限制。
- 运行器配置可以写 `max_permission`,规定这台主机上该运行器最多允许到哪一级。超出的任务在保存时被拒绝,运行时再检查一次。不写表示不限制。
- 完全没有声明权限参数的运行器(例如包装好的自定义命令行)不适用这套级别,任务里不能为它指定级别。
- 每次运行实际使用的级别记录在运行存档里。

## 理由

- 定时任务运行时没有人在场,出错时没有人能当场拦下。
- 提示词常常让 agent 读取网页、邮件、issue 这类外部内容,其中可能夹带指令。只读时最坏的结果是一段错误的文字。
- 多数定时任务只需要读:汇总、检查、生成报告,结果由 Bugu 从输出里取走。
- 默认从严,放开只需改一个选项;反过来默认宽松,出了问题再收紧,就要回头检查所有已有任务。
- 用级别而不是开关,是因为各家工具能提供的限制不一样:有的没有"只写工作目录"这一档。级别也给以后的管理留了位置,增加级别不需要改任务文件的格式。

## 后果

- 需要写文件的任务要多做一步选择。只读运行失败时,运行记录里提示可能需要放开权限。
- 限制由 AI 命令行自己执行,Bugu 只负责传递参数。它的可靠程度取决于那个工具,Bugu 不是沙箱。
- `max_permission` 对所有能调用接口的人一视同仁。按人区分权限需要多个令牌并区分权限,属于 [PRD](../PRD.md) 第 11 章尚未确定的问题,这里不涉及。
