# 0004 单程序多形态,默认由桌面应用承载后台

日期:2026-11-11

## 决定

`bugu` 是单个可执行文件,用子命令决定形态:桌面应用、纯后台、后台加网页面板、命令行客户端。桌面应用默认自己承载后台;启动时若发现本机已有后台在服务,则只作为它的界面。界面只通过 HTTP JSON 接口工作,不使用桌面框架的绑定机制。远程管理即在窗口里打开对方主机的网页面板。

## 理由

- 安装即用,应用不必注册和维护另一个系统服务。
- 界面只走接口,应用窗口、浏览器、远程三种情况是同一条路径,更换桌面框架的代价很小。
- 这套形态在 yetone/magpie 上已被验证。

## 否决的方案

- 应用与后台强制为两个进程:任务不受应用退出影响,但带来服务注册、版本不一致、服务未启动等一系列问题。该模式仍然可用(`bugu daemon install`),只是不作为默认。

## 后果

"退出前提示"和"首次启动询问开机自启"是这个方案成立的前提,列为第一版必须项。没人登录也要运行的机器应按服务器对待。
