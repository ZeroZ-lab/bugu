# 0017 网页前端改用原生 Web Components,不依赖框架

日期:2026-11-13

## 背景

[决策记录 0010](0010-web-react-vite.md) 选了 React。前端只有四个列表页、一个任务表单和一个运行详情,React 和 react-dom 占了产物的大部分体积。项目负责人决定前端不依赖框架,用浏览器自带的自定义元素手写。

## 决定

1. 页面由自定义元素组成(`bugu-app`、`bugu-tasks`、`bugu-task-form` 等),每个是一个继承 `Component` 的类。不用 Shadow DOM,内容直接渲染在元素里,样式仍然只有一份全局的 `style.css`。
2. 渲染由 `web/src/dom.ts` 负责,手写,约两百行:`h` 描述元素,`patch` 把描述对到真实的元素上,标签相同的原地更新。状态是类的普通字段,改完调用 `update()`。
3. `ui/` 里的共用组件是返回元素描述的函数,不是自定义元素:它们只是原生 `button`、`label`、`dialog` 的薄包装,包一层自定义元素会破坏表单和读屏的原生行为。
4. 前端没有运行时的第三方依赖。TypeScript、Vite、Vitest、Playwright 仍作为开发依赖。
5. 0010 的其余决定不变:源码在 `web/`,产物写进 `internal/server/static/` 并提交,`web-check` 检查产物与源码一致。

## 理由

- 0010 放弃旧版手写 JS 的原因是"手写 DOM 的状态同步容易出错,也没有类型检查"。类型检查保留了;状态同步由 `patch` 统一处理,页面代码仍然只写"此刻应该是什么样",不逐个改 DOM。
- 原地更新而不是整段重建:页面每 5 秒刷新一次,重建会丢掉输入框的焦点、正在输入的内容和打开的对话框。
- 不用 Shadow DOM:样式表只有一份,颜色变量和类名全局生效;浏览器测试按角色和文字找元素,不受影响。

## 否决的方案

- Lit:写法接近,但要新增一个运行时依赖。
- 每个组件自己逐项更新 DOM,不写 `patch`:任务表单和步骤卡片里随选项出现、消失的内容很多,逐项维护正是 0010 要避免的。

## 后果

- 产物 `app.js` 从约 281KB 降到约 61KB(压缩传输约 22KB)。
- `dom.ts` 由本项目自己维护。它只做这个前端用到的事:没有异步渲染、没有上下文、没有生命周期以外的钩子。需要这些时先停下来问。
- 列表里的项要给 `key`,否则调整顺序时焦点和输入内容会跟错元素。
- 自定义元素的字段和方法不能与 `HTMLElement` 自带的重名(如 `remove`、`title`、`hidden`),类型检查会报错。
- 没有 DOM 的单元测试环境(那需要新增依赖),渲染行为由 `web/e2e/` 的浏览器测试覆盖。
