# 0006 先用运行器配置和外部脚本扩展,暂不引入插件运行时

日期:2026-11-11

## 决定

第一版沿用 [PRD](../PRD.md) 第 7.2 节的声明式运行器和第 7.11 节的脚本步骤作为扩展入口,不增加通用插件运行时、插件市场或动态界面扩展。

- 运行器配置描述如何调用外部命令行工具,不是可执行的应用插件。
- 自定义任务逻辑由外部脚本承担,仍遵守 [0005](0005-linear-steps.md) 的线性步骤模型。
- 通知渠道等应用功能按现有包职责实现,不为尚未出现的第三方实现预建注册中心、服务依赖解析或插件宿主。
- 只有出现运行器配置和外部脚本无法满足、且需要独立分发和更新的第三方扩展时,才重新评估插件系统。届时新增 ADR,明确扩展点、版本兼容、生命周期、权限和失败处理,不直接扩大现有运行器配置的职责。

## 理由

当前任务是完成调度、执行和结果查看的闭环。完整插件系统会额外引入安装、升级、兼容性和权限管理,这些成本尚无具体扩展需求支撑。

Magpie 的设计提供了两种不同的参考,不能把它们视为同一套插件机制:

- **内置功能模块化**:Go 包静态编译进程序,通过 Manifest 声明服务依赖、设置和界面贡献,运行时负责启停和逆序清理。核心不引用具体插件,插件通过服务交互。见其 [运行时设计](https://github.com/yetone/magpie/blob/main/docs/subsystems/plugin-runtime.md) 与 [注册入口](https://github.com/yetone/magpie/blob/main/plugins/all/all.go)。
- **第三方代码扩展**:需要联网和异步操作的扩展由 Bun 宿主运行,通过逐行 JSON 与 Go 通信;高频网关中间件则使用进程内 JS 引擎。Bun 宿主拥有用户权限,独立进程并不构成权限沙箱。见其 [插件文档](https://usemagpie.ai/docs/plugins) 与 [中间件实现](https://github.com/yetone/magpie/blob/main/internal/middleware/middleware.go)。

Bugu 借鉴明确职责、依赖边界和资源清理的原则,当前不照搬 Magpie 的运行环境和分发体系。

## 后果

- 当前没有可安装的 Bugu 应用插件;自定义运行器仍按 PRD 与内置预设同等对待。
- 运行器、执行器和通知包继续遵守现有依赖允许表,没有新增插件包或第三方依赖。
- PRD 中的 MyGo 插件是桌面框架能力;规划中的 JS 步骤是任务执行能力,两者都不意味着 Bugu 已开放应用插件接口。
- 本决定不新增里程碑交付项,也不把现有扩展需求标为已实现。
