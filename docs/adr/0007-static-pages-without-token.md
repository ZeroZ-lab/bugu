# 0007 网页前端的静态文件不需要令牌,令牌经网址片段交给页面

日期:2026-11-12

## 背景

[0001](0001-http-and-token.md) 规定所有请求必须携带令牌,且令牌只认请求头。浏览器和 webview 在打开一个网址时无法附带 `Authorization` 请求头,所以前端页面本身无法按这条规则加载。

## 决定

1. 后台在同一端口提供前端的静态文件(HTML、JS、CSS)。这些文件不含任何用户数据,不需要令牌。
2. `/api/` 下的所有接口仍然必须携带令牌,没有例外。0001 里"所有请求"在这里收窄为"所有接口请求"。
3. 桌面应用打开窗口时,把令牌放在网址的片段里(`#token=…`)。片段不会发送给服务器,不进访问日志。页面读到后立即从地址栏移除,保存在仅当前标签页有效的会话存储里。
4. 用浏览器直接打开时,页面先要求粘贴令牌。

## 理由

- 浏览器、应用窗口、远程主机三种情况走同一条路径(PRD 5.5),不需要为桌面应用单做一套加载方式。
- 静态文件对任何人都相同,泄露它们不泄露任何东西;能执行命令的入口只有接口,而接口的保护没有放松。
- 令牌不进查询参数和 Cookie,所以不会出现在服务器日志、Referer 和跨站请求里。

## 否决的方案

- 页面由桌面框架从应用内嵌资源加载,再跨源调用接口:要为这个来源放宽来源校验,并依赖框架的绑定机制把令牌交给页面;浏览器里的网页面板还得另做一套。

## 后果

静态文件的响应带内容安全策略,只允许加载同源的脚本和样式,页面里不写内联脚本。静态文件之外的任何路径仍要令牌。
