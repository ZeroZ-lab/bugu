# 0011 步骤之间怎样传数据,怎样声明无事可做

日期:2026-11-12

## 决定

- 每一步的输出保存为运行存档里的文件(`steps/<序号>/stdout.log`),后面的步骤从文件拿到它:
  - 脚本步骤的标准输入是上一步的输出。
  - 提示词和文本步骤里的 `{prev}`、`{steps.<步骤名>.output}` 原样代入。
  - AI 命令行步骤的提示词没有引用任何步骤的输出时,把上一步的输出附在提示词后面。
- 脚本命令里的 `{prev}`、`{steps.<步骤名>.output}` 不把内容拼进命令,而是代入为读取那个文件的命令替换 `"$(cat '<文件>')"`,并按它所在位置的引号(无引号、单引号、双引号)调整写法。命令替换会去掉结尾的换行。
- 脚本步骤以退出码 75(sysexits.h 的 EX_TEMPFAIL)结束表示无事可做:后面的步骤不执行,运行记为成功且无内容,不发业务通知。AI 命令行步骤不用这个约定,它们用静默标记(`silent_if`)。
- 引用只能指向前面已命名的步骤,在保存任务时检查。

## 理由

- 上一步的输出常常来自网页或 AI,里面可能有引号、分号、`$(…)`。直接拼进 `/bin/sh -c` 的命令,等于让这些内容当作命令执行。读文件的写法让输出只作为数据。
- 用文件而不是环境变量传递:环境变量在 Linux 上单个不能超过 128KB,而每一步的输出最多保留 1MB。
- 用户写 `echo {prev}` 或 `echo "{prev}"` 时都应该得到原样的内容,所以要按引号位置调整,不能要求用户记住某一种写法。
- 退出码是脚本最自然的信号,不需要额外的文件或输出格式。75 在常见工具里很少表示别的意思;0、1、2 已被普遍用作成功、失败和用法错误。结果信封(O12)加入后,它是另一种声明方式。

## 后果

- 命令替换会去掉结尾的换行,写在单引号里的 `{prev}` 也会被展开,这与 shell 自身的规则不同,文档和命令行帮助里要说明。
- 运行记录里显示的命令是代入后的样子,其中是输出文件的路径而不是输出内容。
- 想把退出码 75 当作失败的脚本需要改用别的退出码。
