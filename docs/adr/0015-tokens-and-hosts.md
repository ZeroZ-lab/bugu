# 0015 多个令牌、两级访问和登记的其他主机

日期:2026-11-12

## 背景

[0001](0001-http-and-token.md) 规定所有接口请求都要带令牌,但只有一个令牌:数据目录里的 `token` 文件。C5 要求支持多个令牌并能单独作废;G5 和 `--host` 要求本机记下其他主机的地址和令牌。

## 决定

**令牌。**

- 本机令牌仍是 `token` 文件,本机的命令行和桌面应用用它连接,不能作废。
- 另外创建的令牌(`bugu token create <名字>`)存在数据目录的 `tokens.json` 里,只存名字、SHA-256 哈希和创建时间。明文只在创建时返回一次。
- `bugu token revoke <名字>` 作废一个令牌,立即生效。
- 校验时,本机令牌和每个哈希都做常数时间比较。

**两级访问。**

- 本机令牌能访问全部接口。
- 另外创建的令牌能管理任务、运行和设置,但不能管理令牌,也不能读写登记的其他主机(`/tokens`、`/hosts`),返回 `forbidden`。

**登记的其他主机。**

- 存在数据目录的 `hosts.json`,权限 0600,内容是名字、地址和那台主机发的令牌。令牌只能存明文,因为发请求时要带上。
- 命令行的 `bugu host add/list/rm` 和 `--host` 直接读写这个文件,不经过本机后台:只管理远程服务器、本机不运行后台时也能用。
- 网页面板经本机后台的 `/hosts` 读写同一个文件。
- 后台列出主机时逐个检查连接状态:`online`、`offline`、`unauthorized`。连不上只算离线,不表示那台主机的任务失败(G14)。
- 在应用里打开另一个布谷时,窗口载入那台主机自己的网页面板,令牌放在网址片段里(沿用 [0007](0007-static-pages-without-token.md))。片段里还带着本机面板的地址,那边据此显示"返回本机",只接受本机回环地址。本机不代理任何请求。

**明文 HTTP 警告(C6)。** 登记地址是经公网的明文 HTTP 时给出警告。本机、私有网段、100.64.0.0/10(组网工具常用)、`.local`、`.ts.net` 等不算;不做域名解析,认不出的域名按公网算。

## 理由

- 只存哈希:数据目录被人读到时,另外创建的令牌不会跟着泄露;这些令牌常交给别的机器上的 agent 或脚本,泄露面比本机令牌大。
- 两级访问:登记表里有其他主机的令牌。如果交给某个 agent 的令牌也能读到它,一个令牌泄露就会连带其他主机;能创建令牌也就能长期保留访问权。这两件事只在本机做。
- 命令行直接读写 `hosts.json`:它是客户端自己的配置,不是任务数据,不违反"命令行只经接口管理任务";这样在没有本机后台的机器上也能管理服务器。

## 后果

- 远程主机上的令牌只能在那台主机本机管理(登录上去执行 `bugu token`)。
- 本机令牌要更换,得停掉后台、删除 `token` 文件再启动。
- 0001 里"令牌不区分权限"的说法,在这里细化为两级;PRD 第 11 章第 3 条的多用户和权限仍未做。
