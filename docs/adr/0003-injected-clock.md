# 0003 时钟注入,调度按墙上时钟计算

日期:2026-11-11

## 决定

1. 调度不设长定时器。后台按短周期醒来,每次用当前墙上时间计算"现在该触发什么",并持久化每个任务已评估到的时间点。
2. 所有读取时间、等待、定时的代码通过 `internal/clock` 的接口进行,不直接调用标准库的时间函数。

## 理由

- 笔记本睡眠时单调时钟会暂停,"15 小时后"的定时器会在 15 小时的清醒时间之后才触发,任务会悄悄丢失。
- 持久化评估点之后,重启不会重复触发,睡眠后能判断错过了什么。
- 注入时钟让调度、超时、补跑都能在测试里用假时钟瞬间推进,不依赖真实时间,AI agent 可以自行验证。

## 后果

`internal/archtest` 禁止 `clock` 包以外的代码直接使用标准库的时间函数。`schedule` 包保持为纯函数:输入任务、状态、当前时间,输出决定。
