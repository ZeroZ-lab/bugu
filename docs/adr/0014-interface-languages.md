# 0014 界面语言:中文原文作键,中英两种

日期:2026-11-12

## 决定

界面说中文和英文两种语言(G15)。范围包括网页和应用窗口、菜单栏和系统通知、命令行,以及后台给出的错误信息和运行说明。

**原文作键。** 代码里的文字照旧用中文书写,中文原文本身就是查找英文译文的键:

- Go 的译文在 `internal/i18n/en.json`,网页的在 `web/src/locales/en.json`。
- 找不到译文时显示原文。
- 原文只能交给几个固定的函数:Go 里是 `i18n.T`、`i18n.Errorf`、`i18n.N`、`i18n.In`,或写成 `i18n.Text{Zh, En}`;网页里是 `t`、`n`、`tx`,且必须是双引号字符串。
- `internal/archtest` 和 `web/src/i18n.test.ts` 检查四件事:没有绕过这些函数的中文、每段原文都有译文、占位符一致、译文表里没有用不到的条目。

不引入第三方的翻译库。桌面框架的翻译方案需要另加一个前端依赖,并要给每段文字起名字,没有采用。

**错误在显示时才翻译。** `i18n.Errorf` 记下原文和参数,用 `%w` 包住的错误仍能被 `errors.Is` 找到。接口写出错误响应时,按请求头 `Accept-Language` 的语言说;没有这个头时用后台的语言。命令行和网页发请求时都带上自己正在用的语言。

**一个进程说一种语言。**

- 后台按设置 `language`(`auto`、`zh`、`en`)说话。设置存在数据目录的 `settings.json`,经 `GET`/`PUT /api/v1/settings` 读写,命令行用 `bugu language`。
- `auto` 跟随系统:桌面应用用系统设置里的语言顺序,`bugu serve` 用环境变量 `LC_ALL`、`LC_MESSAGES`、`LANG`。中文的各种写法认作中文,其他语言说英文,无从得知时说中文。
- 网页在设置为 `auto` 时跟随浏览器的语言,否则用设置的语言。
- 命令行自己说的语言由 `--lang` 或上面的环境变量决定,不读后台的设置:它常在脚本和别的机器上运行,应当跟随所在的终端。

**记下来的文字不再翻译。** 运行的错误、说明、通知投递的失败原因,在产生时用后台当时的语言写下,之后改了语言也保持原样。任务名、任务输出、cron 表达式、JSON 字段名和状态值不翻译。

## 理由

- 以中文原文作键:现有代码不必为每段文字起名字,读代码时看到的就是界面上的文字;译文缺失时退回原文,不会显示一个键名。
- 检查放在测试里:新写的文字忘了翻译,`make check` 当场失败,不用等人在英文界面里发现。
- 错误延迟翻译:同一个后台同时服务说不同语言的客户端(本机的中文界面和远程的英文命令行),错误信息按请求的人说。
- 运行记录不重新翻译:它们是在某个时刻发生的事的记录,有的还包含任务自己的输出,重写它们得不偿失。

## 后果

- 改中文原文时,对应的英文条目要一起改键,否则检查失败。
- 进程内的语言是全局的。测试里的系统语言固定为中文,改过语言的测试要在结束时改回来。
- 加第三种语言要改两处:Go 的 `i18n.Lang` 和网页的 `Lang` 各加一种,再补一份译文表。
